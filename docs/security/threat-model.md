# Bedrohungsmodell

> **Zweck:** Was geschützt wird, wo die Vertrauensgrenzen verlaufen und welche Angriffe bedacht sind. Jede Gegenmaßnahme verweist auf ihre Fundstelle; offene Punkte stehen in [ROADMAP.md](../ROADMAP.md) und [BACKLOG.md](../BACKLOG.md), nicht hier. Meldeweg für Schwachstellen: [SECURITY.md](../../SECURITY.md). Stand: 21.11.2026.

## 1. Schutzgüter

| Schutzgut                         | Warum                                                                      |
| :-------------------------------- | :------------------------------------------------------------------------- |
| Unterlagen und Dossiers der Akten | Berufsgeheimnis (§ 203 StGB); Mandantentrennung je Kanzlei                 |
| Prüfpfad (`audit_logs`)           | Nachvollziehbarkeit von Übersteuerungen und Exporten (§ 17 BeurkG)         |
| Belegtreue der Ergebnisse         | Eine Angabe ohne nachprüfbare Fundstelle darf nicht als belegt erscheinen  |
| Zugangsdaten und Schlüssel        | Modellzugänge verursachen Kosten, Datenbankschlüssel öffnen alle Mandanten |
| Verfügbarkeit der Analyse         | Termine im Notariat hängen an der Vorbereitung                             |

## 2. Vertrauensgrenzen

1. **Browser → API.** Alles aus dem Browser ist Eingabe: Body, Header, Query, Speicherpfade. Die Identität kommt nur aus der serverseitig geprüften Sitzung.
2. **API → Datenbank und Speicher.** Der Sitzungs-Client unterliegt RLS; Mandantentrennung gilt in PostgreSQL, nicht nur im Code.
3. **API → Modellanbieter.** Dokumentinhalte verlassen das System. Der Anbieter ist Verarbeiter; Stand und offene Fragen: [auftragsverarbeitung.md](../betrieb/auftragsverarbeitung.md).
4. **Dokumentinhalt → Modell.** Hochgeladene Dokumente sind nicht vertrauenswürdig; sie können Anweisungen an das Modell enthalten.
5. **Betreiber → Produktion.** Ein Push auf `main` rollt aus; Migrationen werden einzeln von Hand eingespielt ([ADR 0002](../adr/0002-konsolidierte-domaenenmigrationen.md)).

## 3. Bedrohungen und Gegenmaßnahmen

| Bedrohung                                              | Gegenmaßnahme (Fundstelle)                                                                                                                                                                                                                                                                                                                       | Offen                                                                                                                                                                                                                                                                                           |
| :----------------------------------------------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Zugriff auf Daten einer fremden Kanzlei                | RLS auf allen Tabellen und im Bucket `dossier-files`; Kanzlei aus geprüfter Mitgliedschaft (`resolveSessionOrganizationId`); Nachweis gegen echtes Postgres (`npm run test:db`); [multi-tenancy-compliance.md](../architecture/multi-tenancy-compliance.md)                                                                                      | Servicekonto-Änderungen erzeugen keinen Audit-Eintrag (ROADMAP B.11.7)                                                                                                                                                                                                                          |
| Rechteausweitung innerhalb der Kanzlei                 | `requirePermission` mit Matrix in `rbac.ts`, gespiegelt in SQL und per Test abgeglichen (`rbac-sql-parity.test.ts`); Trigger `organization_members_guard` (eine NOTAR-Mitgliedschaft ändert nur ein NOTAR); Verweigerungen werden als `ACCESS_DENIED` protokolliert                                                                              | —                                                                                                                                                                                                                                                                                               |
| Manipulation des Prüfpfads                             | Hash-Kette per Trigger, Update/Delete/Truncate gesperrt ([ADR 0005](../adr/0005-hash-kette-in-der-datenbank.md)); Begründung ist an den echten Statuswechsel gebunden (`checkStatusOverride`); Trigger `documents_guard_review` gegen Umgehung der Routen                                                                                        | Kein externer Zeitstempelanker                                                                                                                                                                                                                                                                  |
| Anweisungen im Dokument steuern das Modell (Injektion) | Dateinamen werden maskiert (`escapeXmlAttr`); jede Angabe wird deterministisch gegen den Originaltext geprüft, ohne wörtlichen Beleg `NEEDS_REVIEW` ([verifiable-fact-checker.ts](../../src/lib/ai/verifiable-fact-checker.ts)); der Auditor darf Belegtes nicht umschreiben ([auditor-patch-guard.ts](../../src/lib/ai/auditor-patch-guard.ts)) | Ein Dokument kann das Modell weiter beeinflussen; Schutz ist der Beleg-Abgleich, nicht eine Eingabesperre                                                                                                                                                                                       |
| Manipulierte Uploads und Speicherpfade                 | Direkt-Upload über signierte URL in privaten Bucket mit Größenlimit; Pfade aus dem Client nur mit eigenem Kanzleipräfix (`isOwnUploadPath`); Rate-Grenze je Kanzlei für Upload-URLs (`UPLOAD_URL_RATE_LIMIT`, Zählung in PostgreSQL); Dateityp-Prüfung ([file-types.ts](../../src/lib/files/file-types.ts))                                      | Die Grenze zählt abgeschlossene Uploads, nicht ausgestellte URLs; wirksam erst nach Live-Einspielung von `count_recent_uploads`; die Storage-Policy erlaubt Mitgliedern den direkten Upload mit eigener Sitzung an der Route vorbei, die Grenze ist daher Missbrauchsbremse, kein harter Schutz |
| Kostenmissbrauch (Analyse-Läufe)                       | Stundenkontingent je Kanzlei und Tageskontingent samt Obergrenze für Demo-Kanzleien, gezählt in PostgreSQL ([job-orchestration.md](../architecture/job-orchestration.md)); wiederholte Hintergrund-Anfragen mit demselben Schlüssel legen keinen zweiten Job an ([ADR 0006](../adr/0006-idempotenz-ueber-job-id.md))                             | CAPTCHA vor dem Demo-Zugang (BACKLOG); Live-Läufe können das Limit kurz überschreiten                                                                                                                                                                                                           |
| Gefälschte Korrelations-Kennung (`x-request-id`)       | Der Proxy übernimmt nur Kennungen aus `[A-Za-z0-9_-]{8,64}` und ersetzt alles andere; Logs und Sentry erhalten nur den validierten Wert                                                                                                                                                                                                          | Ein Client kann eine gültige Kennung vorgeben und so Logzeilen fremder Anfragen vortäuschen; die Kennung dient der Fehlersuche, nie der Berechtigung                                                                                                                                            |
| Datenabfluss über Logs und Fehlerberichte              | Einziges Logformat ohne Freitext (`LogEventSchema`, `.strict()`); Sentry nur mit Allowlist-Tags ([scrub-event.ts](../../src/lib/observability/scrub-event.ts)); feste Fehlermeldungen in Antworten                                                                                                                                               | —                                                                                                                                                                                                                                                                                               |
| Abfluss zum Modellanbieter                             | Verarbeiter, Regionen und Vertragslage sind erfasst ([auftragsverarbeitung.md](../betrieb/auftragsverarbeitung.md))                                                                                                                                                                                                                              | AVV, Anthropic ohne EU-Verarbeitung, Gemini-Zugang auf bezahlt prüfen (ROADMAP C.7); bis dahin keine echten Akten                                                                                                                                                                               |
| Umleitung nach Anmeldung (Open Redirect), Framing      | `safeRedirectPath` für alle Weiterleitungsziele; HSTS, `X-Frame-Options: DENY`, CSP über [security-headers.ts](../../src/lib/security/security-headers.ts)                                                                                                                                                                                       | —                                                                                                                                                                                                                                                                                               |
| Testmodus in Produktion                                | `MOCK_AI` bricht in Produktion Start und Build ab ([env.ts](../../src/env.ts))                                                                                                                                                                                                                                                                   | —                                                                                                                                                                                                                                                                                               |
| Schwachstelle in Abhängigkeiten oder Pipeline          | Dependabot, `npm audit` ab Stufe high in CI, statische Analyse mit Semgrep in CI und vor dem Push (`audit:sast`), GitHub Actions per Commit-SHA gepinnt                                                                                                                                                                                          | Kein SBOM, keine Image-Prüfung (kein eigenes Image)                                                                                                                                                                                                                                             |
| Ausfall oder Datenverlust                              | Hintergrund-Jobs mit Checkpoint und Heilung ([ADR 0001](../adr/0001-hintergrundverarbeitung-mit-after.md)); Betriebsablauf in [runbook.md](../betrieb/runbook.md)                                                                                                                                                                                | Kein Staging, keine automatische Datensicherung, keine Alarmierung (ROADMAP C.7)                                                                                                                                                                                                                |

## 4. Nicht im Modell

Endgeräte der Nutzer, Kompromittierung der Anbieterkonten (Supabase, Vercel, GitHub) und Angriffe auf die Anbieter selbst. Für sie gelten die Maßnahmen der Anbieter und die Kontoabsicherung des Betreibers.
